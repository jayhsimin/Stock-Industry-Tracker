# MA5/10/20 支撐/破位策略（草案，模擬單）

跟現有波段策略（`trading/`）、當沖策略（`trading/daytrade/`）完全隔離的**第三個**獨立模組。
**目前只能下模擬單**，而且**沒有排進任何排程**——寫這份規則是使用者明確要求「在不影響目前虛擬交易執行的
前提下」做的，所以連自動執行都先不開，確保不會跟現有兩套策略搶資金/搶部位，也不會有任何意外副作用。

## 策略概念（使用者指定，已對照網路資料驗證）

均線在股價站上方時會形成動態支撐——回測均線時買盤會進場守住；一旦股價**明確跌破所有均線**，
均線會由支撐轉為壓力，跌勢通常會延續，直到股價找到新的整理區間才會止穩。這是使用者描述的概念，查證
後跟國內外技術分析資料的說法一致：

- [20 Moving Average Pullback Strategy](https://www.tradingsim.com/blog/20-moving-average-pullback) —
  回檔到上升中的均線、買盤守住後進場，停損設在均線下方或回測低點下方
- [How to Use Moving Averages with Support and Resistance](https://www.luxalgo.com/blog/how-to-use-moving-averages-with-support-and-resistance/) —
  均線作為動態支撐/壓力的機制說明
- [均線支撐壓力怎麼用？動態防線完整說明](https://capfutures.com/ma-dynamic-support-resistance/) —
  明確跌破後均線由支撐轉壓力，趨勢可能轉向；短暫跌破後迅速收回則可能只是假跌破/洗盤
- [【3分鐘學技術分析】掌握均線](https://vocus.cc/article/66a666dbfd89780001f46964) —
  回測量縮、守住後量增，是有效支撐的訊號

## 規則

**進場（四個條件同時成立）**

1. 碰觸支撐：**昨天**收盤價在MA5／MA10／MA20**任一條**的±1.5%範圍內
2. 站回支撐（跨兩日確認，2026-10改版）：**今天**收盤價同時高於昨天收盤、且 ≥ 昨天碰到的那條
   （那些）均線——不是昨天碰、今天隨便收在均線上就算數，要真的比昨天收高才算反彈有延續性
3. 量增確認：Shioaji`volume_ratio` ≥ 1.5倍（2026-10從1.3調整，比照波段策略已驗證過的門檻）
4. 流動性門檻：當日累積成交金額 ≥ NT$1億

**為什麼不是同一天碰觸+站回**：原始版本（同一天碰觸、同一天就算站回）回測1個月是虧損的
（見下方「回測記錄」），支撐破位出場佔了一半交易、而且每次都虧——代表同一天的碰觸+站回太容易被
單日雜訊誤判成有效支撐。改成跨兩日確認後，這個問題大幅緩解（細節見下方回測記錄）。

**出場（任一條件觸發）**

- **支撐破位**（這套策略的核心機制）：收盤價跌破**全部**還有效的均線——不是跌破其中一條，是全部都
  跌破，代表這些均線已經由支撐轉為壓力。這個條件獨立於下面的停損%，就算虧損還沒到-6%也會先因為這個
  觸發出場，因為研究顯示這種破位通常會續跌，不值得等固定停損百分比
- 停損：未實現報酬 ≤ -6%
- 停利：未實現報酬 ≥ +10%
- 持有超過5個交易日

**沒有額外設計「破位後N天內不能重新進場」的規則**——這是進場條件本身的自然結果：破位後股價在均線
下方，不滿足「碰觸+站回」的進場定義，要等股價重新漲回來碰到並站上某條均線才會再次觸發訊號，等於
自動要求先出現整理/止穩才會考慮重新進場。

## 資金/風險隔離

- 自己的資金池：`config.MAX_TOTAL_POSITION_COST_NTD = NT$200,000`，跟波段策略的60萬、當沖的兩個60萬
  池完全分開獨立計算，不會互相排擠
- 自己的持倉檔：`trading/ma_touch/positions_state.json`（gitignore）
- 下單走`trading/executor.py`同一套兩段式防呆閘門（`--live` + `TRADING_LIVE_CONFIRM`環境變數缺一都是
  模擬單），跟其他策略共用同一個安全機制，不是重新發明
- 簡化版的下單數量邏輯（`scan.py`自己的`shares_to_buy()`）：買得起1張整股就買，買不起就跳過——
  不像波段策略最近改用零股精準湊單，這是全新、沒驗證過的策略，先從最簡單的規則開始

## 跟均線總覽dashboard分頁的關係

**沒有關係**，純粹是週期數字一樣（都是5/10/20）方便使用者對照理解。`build_ma_cache.py`只負責畫圖用
的資料，這套策略的`signals.py`/`scan.py`完全獨立計算自己需要的MA，兩邊程式碼沒有互相import。

## 回測記錄（`backtest.py`，正式規則、非單日測試）

對182檔concept_map股票、2026-09-13~2026-10-13（1個月）回測，重用`signals.py`的`check_entry`/
`check_exit`（不是重新實作）：

| | 原版（同日碰觸站回，已否決） | 現版（跨兩日確認） |
|---|---|---|
| 交易次數 | 14 | 9 |
| 勝率 | 21.4% | 55.6% |
| 總損益 | NT$-10,551 | NT$+21,910 |
| 平均報酬 | -1.47% | +1.74% |
| 支撐破位出場(support_broken) | 7筆、0%勝率 | 1筆、0%勝率 |

跨兩日確認版本把假突破問題（support_broken佔一半交易、每次都虧）大幅降低，出場主力變成
`max_hold_days`（6筆、67%勝率），是健康得多的分布。**但9筆交易的樣本量仍然偏小**，這個正報酬的
統計把握度不足，不能當成「已驗證」，只是機制層級的改善（support_broken 7→1）有數據支持，方向
正確。

**拉長到6個月（2026-04-16~2026-10-13，Shioaji歷史資料上限附近，125筆交易）重新驗證後**：
勝率掉到42.4%、平均報酬+0.53%、總損益NT$5,320（20萬預算上幾乎打平）。support_broken出場回升到
37筆（29.6%，比例跟原版的50%比起來確實降低了，但絕對次數和0%勝率都還在），按週損益正負交替
（最好一週+15,171、最差一週-10,126），沒有方向性。**1個月那次的改善是小樣本幸運，不是策略真的
變好了。**

**用72組參數網格搜尋+train/test切分（73天/50天）再測一次**：train上選出來的「最佳參數」
（touch_tolerance=2%、量比1.3、停損-5%、停利12%、最長持有8天）在train上非常漂亮
（勝率57.1%、+5.06%、+NT$120,725），但同組參數在held-out test上**直接翻負**
（勝率24.4%、-1.13%、-NT$16,996）——教科書等級的過度配適。反而是完全沒調過的現行預設參數，
test表現（+0.07%、+NT$6,705）比「精心調出來的最佳解」更好。**決定不採用grid search找到的任何
參數組合，維持現行config.py設定不變。**

## 目前狀態：草案，未排程，最終結論

跨兩日確認的修正方向是對的（support_broken假突破問題確實減少），但完整樣本+交叉驗證都證實
**這套策略目前沒有找到經得起驗證的可靠優勢**，跟這個專案測過的其他策略（K棒反轉、真假突破、
價格動能）結論一致：
- `trading/decisions.json`裡標記為`status: draft`，不是`active`
- 沒有建立任何Windows排程任務，`scan.py`需要手動執行才會跑
- 不建議再繼續調整參數追求更漂亮的回測數字——72組網格搜尋已經示範過這條路只會找到過度配適的噪音
- 如果未來想重新評估，應該等Shioaji歷史資料累積得更久（目前卡在~250個日曆天的上限附近），用更長
  的獨立窗口驗證，而不是在同一份資料上繼續調參數

python -m trading.ma_touch.backtest --days 30         # 正式規則回測（可調整--days）
python -m trading.ma_touch.cross_validate --days 180  # 參數網格搜尋+train/test切分（避免過度配適）
python -m trading.ma_touch.test_intraday_replay       # 單日逐分鐘重播測試（診斷用）
python -m trading.ma_touch.test_top20_volatility      # 今日量能+波動前20檔逐分鐘重播測試（診斷用）
